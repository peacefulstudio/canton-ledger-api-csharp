## [0.2.0-preview.1] - 2026-07-04

### Changed — BREAKING

- **The typed subscription stream never silently drops an event — unclassifiable events surface as `ContractStreamEvent<T>.Unclassified`** (`Canton.Ledger.Grpc.Client`, ADR 0003, #150). `ContractStreamProjector` previously hit a silent `continue` whenever it could not classify a delivered event to the subscribed marker `T`, dropping it from the stream. Several shapes triggered that drop and now surface instead: any `Created`/`Archived`/`Exercised`/`Assigned`/`Unassigned` event whose template or interface does not match the subscribed marker `T`; an interface-typed `ArchivedEvent`/`ExercisedEvent` the participant left with empty `implemented_interfaces` despite `include_interface_view` (#142); an `UnassignedEvent` on an interface-typed stream, which carries no interface marker at all (#140); a transaction or reassignment event whose synchronizer id is missing; and any event whose oneof case this layer does not recognise. Each now yields `ContractStreamEvent<T>.Unclassified(Offset, Kind)` — the neutral, transport-agnostic variant added upstream in `Daml.Runtime`, carrying only the ledger offset and a short diagnostic kind (no wire bytes). Source-breaking for any consumer whose `switch` over `ContractStreamEvent<T>` is exhaustive: add an `Unclassified` arm — persist `Offset` to advance the resume point, log `Kind`, and do not treat it as your typed contract. Member of the v0.2.0 breaking bundle. The active-contract snapshot path (`SubscribeActiveAsync`) reaches the same parity below (#179).
- **`SubscribeActiveAsync<T>` now returns `IAsyncEnumerable<ContractStreamEvent<T>>` (was `IAsyncEnumerable<ContractStreamEvent<T>.Created>`), so the active-contract snapshot reaches no-silent-drop parity with the live stream** (`Canton.Ledger.Grpc.Client`, ADR 0003, #179). An `ActiveContract`/`IncompleteUnassigned`/`IncompleteAssigned` snapshot entry whose created event cannot be paired with a synchronizer id now yields `ContractStreamEvent<T>.Unclassified(Offset, UnclassifiedKind.MissingSynchronizerId)` instead of being logged and dropped; an entry whose template/interface does not match the subscribed marker `T` yields `Unclassified(Offset, UnclassifiedKind.CreatedEvent)` — the same kind the live stream already uses for that shape. Source-breaking for any consumer whose `switch` over the yielded events assumed `Created` exclusively: add an `Unclassified` arm, same as for the typed subscription stream. Member of the v0.2.0 breaking bundle.
- **`SynchronizerId` is now present on the `Created`/`Archived`/`Exercised` read-event variants** (`Canton.Ledger.Grpc.Client`, #151). Typed subscription events lifted from a `Transaction` carry that transaction's `synchronizer_id`, and the active-contract path carries the synchronizer each contract is active on, so a consumer reconstructing state across a multi-synchronizer topology can attribute every event to its synchronizer without a side lookup. Follows the upstream `Daml.Runtime` surface where `SynchronizerId` became a required constructor argument on these variants — source-breaking only for code that constructs them by hand; readers gain a property.
- **PQS typed filter field names now resolve from codegen `[DamlField]` metadata instead of a PascalCase→camelCase transform** (`Canton.Ledger.Pqs.Client`, ADR 0009, #155). `Filter.Field<T>(x => x.Prop, value)` reads the wire field name from the `[DamlFieldAttribute]` the codegen emits on each generated property, so the JSONB key it queries (`payload->>'…'`) matches the on-ledger name exactly. The old string transform is removed along with the internal `FieldNameResolver`. Two consumer-visible consequences: (1) for any field whose C# property name does not cleanly invert to its Daml field name — snake_case (`created_at`, previously mis-queried as `createdAt`), reserved-word escapes (`@operator`), or colliding names — the resolved key changes to the correct wire name, so filters that silently returned empty now return the right rows; (2) a template type generated by a **pre-metadata codegen** (no `[DamlField]` attribute) now throws `InvalidOperationException` the first time the DSL resolves one of its fields, instead of guessing a key — there is no mixed-codegen-version path, so regenerate all Daml bindings with codegen ≥ 0.2.0 before using the typed filter DSL.
- **`SubmitAndWaitAsync` now returns `SubmitAndWaitResult` (was `string`) and the fire `Submit` now returns `CommandId` (was `string`), surfacing the effective `command_id` on every await-submission path** (`Canton.Ledger.Grpc.Client`, ADR 0007, #190). The client mints a stable `command_id` for a submission that omits one and pins it onto the wire `Commands` before the RPC; both methods now report the effective id back — `SubmitAndWaitAsync` as `SubmitAndWaitResult(CommandId, UpdateId, CompletionOffset)`, `Submit` as a typed `CommandId` — so a caller can correlate the completion or retry under ledger-side deduplication even when the id was assigned by the client. `TransactionResult` also gains a `CommandId` (projected from the transaction's `command_id`, `default` when the participant recorded none — e.g. a point read of a transaction the reader did not submit), so every `Try*` path surfaces it via `ExerciseOutcome<TransactionResult>`. Source-breaking for callers that consumed the former `string` returns: read `.UpdateId` off `SubmitAndWaitResult`, and `.Value` (or `(string)id`) off the returned `CommandId`. Member of the v0.2.0 breaking bundle. Follows the upstream `Daml.Ledger.Abstractions`/`Daml.Runtime` surface that adds `SubmitAndWaitResult` and appends `CommandId` to `TransactionResult`.
- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` `0.2.0-preview.1` → `0.2.0-preview.2`**, the runtime line carrying the #470 `Unclassified` and #471 `SynchronizerId` surface the two changes above consume.
- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` `0.2.0-preview.2` → `0.2.0-preview.3`**, the runtime line carrying the widened `SubscribeActiveAsync<T>` return type the #179 change above consumes.
- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` `0.2.0-preview.3` → `0.3.0-preview.1`**, the runtime line carrying the `SubmitAndWaitResult` type and the `TransactionResult.CommandId` surface the change above consumes — upstream released it under a minor bump because it breaks the `ILedgerClient` contract.

### Added

- **`CommandsSubmission.WithSynchronizerId` is wired through to the wire** (`Canton.Ledger.Grpc.Client`, #151). When a submission carries a synchronizer id, `BuildCommands` sets it on the gRPC `Commands.synchronizer_id`, pinning that one submission to a synchronizer; when it does not, the field is left unset. No client-wide synchronizer default is introduced, so unpinned submissions behave exactly as before.
- **`IAdminClient.AllocatePartyAsync` gains an optional `synchronizerId` parameter** (`Canton.Ledger.Grpc.Client`). When set, it fills `AllocatePartyRequest.synchronizer_id`, pinning the allocation to one synchronizer; when `null` (the default) the field is left unset and the participant falls back to its single connected synchronizer, exactly as before. Required on a participant connected to more than one synchronizer — e.g. a canton-localnet multi-synchronizer profile (ADR-0004) — where an unpinned allocation otherwise fails with `PARTY_ALLOCATION_CANNOT_DETERMINE_SYNCHRONIZER`. No client-wide synchronizer default is introduced, mirroring `CommandsSubmission.WithSynchronizerId`. Pair it with `LedgerClient.GetConnectedSynchronizersAsync` to pick the target synchronizer at run time.
- **`Canton.Ledger.Kernel` is the transport-neutral client kernel** (ADR 0006, #149; renamed from `Canton.Ledger.Auth` in #202 before these IDs went public — the auth-only name understated a package that also carries the telemetry convention and retry pipeline), organizing three explicit modules both the gRPC client and the future JSON client consume as peers: `Kernel.Authentication` (`ITokenProvider` plus the OAuth2 client-credentials token generation) sits at the bottom of the kernel's namespace DAG — it depends on neither of the other two modules, keeping a later extraction of auth into its own package non-breaking; `Kernel.Telemetry.LedgerActivitySource` centralizes the `ActivitySource` naming convention (`NameFor<T>()`, `Create<T>()`, `StartActivity<T>()`) that `LedgerClient`/`AdminClient`/`PqsClient` previously duplicated ad hoc — all now delegate to it with no change to their `ActivitySourceName` values or emitted span names; `Kernel.Resilience.RetryOptions`/`RetryPipelineFactory` add an opt-in Polly `ResiliencePipeline` seam, disabled by default (`Create` returns `ResiliencePipeline.Empty`, a genuine no-op, unless `RetryOptions.Enabled` is set). Nothing in the gRPC client wires the retry pipeline into a live call path yet — it is a seam ready for a transport to opt into, not an active policy — so existing gRPC behavior is unchanged. The kernel takes a new `Polly.Core` dependency (BCL `Activity` only for telemetry — no OpenTelemetry SDK dependency is introduced, ADR 0010). `Canton.Ledger.Pqs.Client` now references the kernel to reach `LedgerActivitySource`, so a PqsClient-only consumer picks up `Polly.Core` and `Microsoft.Extensions.Http` transitively where its graph previously carried neither (#202).
- **The opt-in retry pipeline is now wired through every `LedgerClient` unary RPC** (`Canton.Ledger.Grpc.Client`, ADR 0006, #191), activating the seam #149 landed unused. Each unary call — both submit-and-wait paths, the fire `Submit`, and the `GetLedgerEnd`/`GetConnectedSynchronizers`/`GetLedgerApiVersion`/point-read reads — executes through the Polly `ResiliencePipeline` built from a new `LedgerClientOptions.Retry` (`RetryOptions`, bound from `Canton:Ledger:Retry`). It stays **disabled by default**, so transport behavior is byte-for-byte unchanged (empty pipeline, one call) unless a consumer opts in. The retry boundary sits *below* command construction, so every attempt resubmits the same `command_id` and ledger-side deduplication makes a resubmission idempotent — the pipeline itself confers no idempotency (ADR 0006). Only transient transport failures are retried (gRPC `Unavailable`/`DeadlineExceeded`), classified by a predicate the client supplies to `RetryPipelineFactory.Create` so no `Grpc.Core` type enters the transport-neutral kernel; Daml business errors (surfaced through `ExerciseOutcome`) and non-transient status codes are never retried. `LedgerClientOptions.Timeout` is a **per-attempt** deadline — each attempt is granted a fresh budget rather than sharing one across the sequence — a cancelled `CancellationToken` halts retries promptly (even mid-backoff), and each retry attempt emits a span on the shared `LedgerClient` `ActivitySource`.
- **`LedgerClient` fills out the rest of the D1 grant surface: `GetConnectedSynchronizersAsync`, `GetUpdateByOffsetAsync`/`GetUpdateByIdAsync`, and `GetLedgerApiVersionAsync`** (`Canton.Ledger.Grpc.Client`, ADR 0005, #157). `GetConnectedSynchronizersAsync(party?, participantId?)` wraps `StateService.GetConnectedSynchronizers`, returning the new `ConnectedSynchronizer(SynchronizerAlias, SynchronizerId, Permission)` record for each synchronizer the participant is connected to. `GetUpdateByOffsetAsync(offset, submitter)` and `GetUpdateByIdAsync(updateId, submitter)` wrap `UpdateService`'s point-read RPCs, scoping visibility to the submitter's combined `ActAs ∪ ReadAs` parties with no template/interface restriction, and project the result through the same `TransactionResult` shape `TrySubmitAndWaitForTransactionAsync`'s success case already returns — they throw `InvalidOperationException` if the looked-up update turns out to be a reassignment or topology transaction rather than a ledger transaction, `ArgumentOutOfRangeException` if `offset` is zero or negative, and `ArgumentException` if `updateId` is null, empty, or whitespace. `GetLedgerApiVersionAsync()` wraps `VersionService.GetLedgerApiVersion`, returning the reported version string. All four are additive methods on the concrete `LedgerClient` (the transport-neutral `ILedgerClient` upstream doesn't carry them yet, matching the precedent set by `Submit`/`CompletionStreamAsync`); party and user management are unchanged — they already existed in `AdminClient` and remain out of this issue's scope per ADR 0005's operator/topology-admin exclusion.
- **Client spans carry OpenTelemetry semantic-convention attributes** (`Canton.Ledger.Grpc.Client`, `Canton.Ledger.Pqs.Client`, ADR 0010, #154). Every gRPC call span (`LedgerClient`/`AdminClient`) now starts as `ActivityKind.Client` and carries `rpc.system`/`rpc.service`/`rpc.method`/`server.address`/`server.port`; a call that fails with an `RpcException`, a `DamlError` outcome, or an `InfraError` outcome now records `ActivityStatusCode.Error` plus `error.type` (and `rpc.grpc.status_code` for gRPC failures) on the span, where none of that was recorded before. No OpenTelemetry SDK dependency is introduced — spans remain BCL `System.Diagnostics.Activity` only.
- **New opt-in `Canton.Ledger.OpenTelemetry` package** (ADR 0010, #154) exposes `OpenTelemetry.Trace.CantonLedgerTracerProviderBuilderExtensions.AddCantonLedgerInstrumentation()`, a `TracerProviderBuilder` extension that registers the `LedgerClient`/`AdminClient`/`PqsClient` `ActivitySource`s plus Npgsql's own PostgreSQL tracing (`.AddNpgsql()`) — the only assembly in this repo that depends on the OpenTelemetry SDK. W3C trace-context propagation needs no inject/extract code: the BCL `SocketsHttpHandler` already injects `traceparent`/`tracestate` once a sampled `Activity` is current. Ships in the `0.2.0-preview.1` package set; giving it an independent version line is deferred to a later release.

### Changed

- Bump `Peaceful.Extensions.Logging` to 0.2.1-preview.3 (#200)
- **The span attribute tag names `LedgerClient`/`AdminClient`/`PqsClient` emit are renamed onto the `daml.*`/`canton.*` taxonomy** (`Canton.Ledger.Grpc.Client`, `Canton.Ledger.Pqs.Client`, ADR 0010, #154). This is a one-time pre-1.0 normalization of the ad-hoc tag names the prior instrumentation used — a telemetry-shape change only, with no C# API impact, so it is **not** part of the v0.2.0 compile-breaking bundle recorded above. Old → new: `choice`→`daml.choice`, `contractId`→`daml.contract_id`, `template.type`→`daml.template_id`, `packageId`→`daml.package_id`, `offset`→`canton.offset`, `fromOffset`→`canton.from_offset`, `submitter.actAs`/`readAs`→`canton.submitter.act_as`/`read_as`, `updateId`→`canton.update_id`, `party`→`canton.party_id`, `participantId`→`canton.participant_id`, `partyIdHint`→`canton.party_id_hint`, `userId`→`canton.user_id`, `submissionId`→`canton.submission_id`; PQS's `pqs.template`/`pqs.result.count` become `daml.template_id`/`canton.pqs.result_count`. Any dashboard, alert, or saved trace query pinned to the old tag names breaks and must be repointed at the new names; acceptable pre-1.0 per ADR 0010.

### Fixed

- **Interface-typed subscriptions now decode `Created`/`Assigned` payloads from the matched `interface_views[].view_value` instead of the implementing template's `create_arguments`** (`Canton.Ledger.Grpc.Client`, ADR 0003, #127). `ContractStreamProjector` previously populated the read-event payload from `create_arguments` for every subscribed marker `T`, template or interface alike — for an interface-only subscription that field reflects a different (or entirely absent) shape than the interface's own view, so a consumer's `TView.FromRecord(created.Payload)` decoded the wrong data. Payloads for interface-typed `T` are now decoded from that interface's `view_value`, matched by interface id, across the transaction stream, the active-contract snapshot, and reassignment `Assigned` events. Per ADR 0003's no-silent-drop invariant, an interface view the participant could not compute (a non-OK `view_status`) or left unset despite matching the interface id now yields `ContractStreamEvent<T>.Unclassified(Offset, UnclassifiedKind.InterfaceViewUnavailable)` rather than a defaulted or wrong-shaped payload. Template-typed subscriptions are unaffected.

## [0.1.5-preview.2] - 2026-06-30

### Changed — BREAKING

- **Adapted to `daml-codegen` 0.2.0: `ILedgerClient.SubmitAsync` is renamed to `SubmitAndWaitAsync`** (`Canton.Ledger.Grpc.Client`, ADR 0007, #153). The upstream abstraction renamed the submit-and-wait method to name it honestly — it submits and blocks until the participant returns the resulting transaction's update id, never a fire-and-forget submit — which also frees the `Submit` name for the new true fire path (below). `LedgerClient`'s public method follows suit: `Task<string> SubmitAsync(CommandsSubmission, CancellationToken)` becomes `Task<string> SubmitAndWaitAsync(...)` with identical signature and behaviour, and the private helper that issues the `SubmitAndWait` gRPC call is renamed `SubmitAndWaitCoreAsync` (matching the existing `TrySubmitCoreAsync` shape). This is a consumer-visible breaking change to canton's own client: callers of `LedgerClient.SubmitAsync` / `ILedgerClient.SubmitAsync` must call `SubmitAndWaitAsync` instead — a pure rename, no argument or return-type change.
- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` `0.1.8-preview.5` → `0.2.0-preview.1`**, the runtime line carrying the renamed `ILedgerClient` contract.

### Added

- **`SubscribeActiveAsync<T>` widened from `where T : ITemplate` to `where T : IDamlType`** (`Canton.Ledger.Grpc.Client`, #141). The active-contract subscription read path now accepts interface markers as well as templates: stream filtering routes through `MarkerMatcher<T>` (`StreamFilterIdentifier` / `MatchesProtoCreated`), so an interface-typed subscription matches `CreatedEvent`s by interface id while template markers keep matching by template id. This lifts the `ITemplate`-only restriction that `[0.1.5-preview.1]` recorded as "blocked on an upstream release" — `Daml.Runtime`/`Daml.Ledger.Abstractions` `0.2.0-preview.1` supplies the widened marker surface. Non-breaking: existing `ITemplate` subscriptions compile and behave unchanged.
- **Fire-and-forget `LedgerClient.Submit`** (`Canton.Ledger.Grpc.Client`, ADR 0007, #153). Hands the commands to `CommandSubmissionService.Submit` and returns once the participant accepts them for processing (not when the transaction commits), yielding the `command_id` for correlation. The verdict arrives separately on `CompletionStreamAsync`. No client-side pending-set: the consumer correlates by `command_id`/`submission_id` and owns its offset. The XML doc carries the Polly double-submit caveat — retrying the call (by hand or via a resilience policy) can resubmit commands the participant already accepted before the transport surfaced the failure, unless the `command_id` is reused for ledger-side deduplication.
- **`LedgerClient.CompletionStreamAsync`** (`Canton.Ledger.Grpc.Client`, ADR 0007, #153). Surfaces `CommandCompletionService.CompletionStream` as `IAsyncEnumerable<Completion>`, scoped to the submitter's parties from a caller-supplied `beginExclusiveOffset`; offset checkpoints are skipped and stream faults rethrow the `RpcException`. To catch the completion of a command you are about to `Submit`, capture the offset *before* submitting — a completion can be emitted before the stream is opened.

## [0.1.5-preview.1] - 2026-06-23

### Changed — BREAKING

- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` to `0.1.8-preview.2`** (public nuget.org releases of the runtime line) and adopted its typed submission surface (#103). `LedgerClient` follows the new `ILedgerClient` contract: the `string actAs` convenience overloads of `TryCreateAsync`, `TryExerciseAsync`, `TryExerciseForCreatedAsync`, `SubscribeAsync`, and `SubscribeActiveAsync` are gone — pass a `Party` (implicitly convertible to `SubmitterInfo`) or a full `SubmitterInfo` instead. `CommandsSubmission.CommandId`/`WorkflowId` are now the `CommandId`/`WorkflowId` value types and `ExerciseCommand` carries `ContractId`/`ChoiceName` value types, so a bare string can no longer be transposed into the wrong slot at a call site.
- **`DamlValueConverter.ToProtoValue` emits `Numeric` in canonical unpadded decimal form** (`Daml.Runtime.Grpc`), the commitment-grade wire shape per codegen ADR-0011: trailing zeros stripped, at least one fractional digit, never scientific notation — `1.50m` → `"1.5"`, `0m` → `"0.0"`, `42m` → `"42.0"`. The gRPC wire encoder now agrees with the runtime's `DamlJsonSerializer`, so the wire shape no longer depends on the `decimal`'s construction scale (previously `0m` → `"0"`, `1.50m` → `"1.50"`).

### Added

- **Interface-view extraction on `CreatedContract`** (`Canton.Ledger.Grpc.Client`, #51). `TransactionResultProjector` now maps each `CreatedEvent.interface_views[].interface_id` into the new init-only `CreatedContract.InterfaceIds` (`IReadOnlyList<Identifier>`, from `Daml.Runtime`); `InterfaceIds` is empty when the transaction was not fetched with an interface filter. `ProjectToContractId<TMarker>` is widened to `where TMarker : IDamlType` and matches interface markers (`TMarker : IDamlInterface`) against `InterfaceIds` — module + entity name, package-id-agnostic, mirroring the existing template-id match — returning `None`/empty (never throwing) when no interface view is present, while `ITemplate` markers keep matching `TemplateId` as before. Non-breaking addition. NOTE: the public read-path surface (`ILedgerClient.TryExerciseForCreatedAsync<I>`, `TransactionResultExtensions.Single<I>/All<I>`) is still constrained to `ITemplate` in `Daml.Ledger.Abstractions`/`Daml.Runtime` `0.1.8-preview.4`; widening that surface to `IDamlType` is blocked on an upstream release.

- **`NOTICE` file** at the repository root declaring the product, copyright, and Apache-2.0 attribution alongside `LICENSE`.

- Add CI-verified platform support across the full OS × architecture matrix: every shipped package builds and passes the unit test suite on Linux, Windows, and macOS, on both amd64 and arm64 (matching `daml-codegen-csharp` #314).
  Integration tests against Canton localnet continue to run on linux-amd64 only.

- **Package management methods on `IAdminClient`/`AdminClient`** (`Canton.Ledger.Grpc.Client`, #7). `ListKnownPackagesAsync()` returns every Daml-LF package known to the participant as a new `PackageDetails` record (id, name, version, size as `long`, known-since); `GetPackageAsync(packageId)` downloads a package as a new `PackageArchive` record carrying the `daml_lf` archive payload together with its hash and hash function, and propagates `RpcException` (`NotFound`) for unknown package IDs; `ListVettedPackagesAsync(packageNamePrefixes)` returns the vetted-package topology state flattened into a new `VettedPackage` record (package id/name/version plus the participant and synchronizer it is vetted on), optionally filtered by package-name prefixes, transparently following server pagination to return the complete result set, and throwing `InvalidOperationException` if the server echoes a page token without progressing; `UploadDarAsync(darFile, submissionId)` uploads a DAR to the participant — note the ledger's default `vetting_change` is `VETTING_CHANGE_VET_ALL_PACKAGES`, so the upload also vets all packages in the DAR; `ValidateDarAsync(darFile)` runs the same checks without persisting or vetting anything and throws `RpcException` on validation failure. DAR bytes and package IDs are argument-validated up front (`ArgumentNullException`/`ArgumentException`). Backed by the existing generated `PackageManagementService` and `PackageService` gRPC stubs, with the established auth-header, deadline, and OpenTelemetry activity conventions. Non-breaking for `IAdminClient` consumers; implementors of the interface must add the five methods.

- **Live round-trip coverage for variants and non-default-scale numerics** (`Canton.Ledger.Grpc.Client.Integration.Tests`). The `richtypes` fixture DAR now carries an `Outcome` variant — including the `Win` record-payload case (`prize : Numeric 2; tier : Text`) — and a `fee : Numeric 2` field; `RichTypesRoundTripTests` creates and reads both back through Canton localnet, gating the ADR-0011 numeric wire form and the ADR-0012 variant round-trip end to end. Generated fixtures regenerated with `dpm-codegen-cs:0.1.8-preview.1`.

- **`TransactionResult.ExerciseResult<TReturn>(choiceName)` and `AllExerciseResults<TReturn>(choiceName)` extension methods** (`Canton.Ledger.Grpc.Client`). They locate exercised events by ordinal choice name in `TransactionResult.ExercisedEvents` and deserialize each `ExerciseResult` through the existing `Daml.Runtime` `FromDamlValue<T>` path, giving codegen consumers a typed surface for non-CID choice results (e.g. `choice GetTrailingTwap : Decimal`). `ExerciseResult<TReturn>` mirrors the `Single<T>()` cardinality contract — it throws `InvalidOperationException` on zero or more than one match; `AllExerciseResults<TReturn>` returns every match in transaction order (empty list when none). Both accept the choice as `string` or as the `Daml.Runtime` `ChoiceName` value type, so `ExerciseCommand.Choice` flows through without unwrapping. Non-breaking addition.

### Changed

- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` `0.1.8-preview.2` → `0.1.8-preview.4`** (#51), which adds `CreatedContract.InterfaceIds` and the `IDamlType`/`IDamlInterface` markers consumed by interface-view matching.
- **Relocated the architecture overview to `docs/public/architecture-overview.md`** (was `docs/architecture-overview.md`); the README link now points at the new path.
- **`ClientCredentialsProvider` now resolves its token endpoint at construction** (`Canton.Ledger.Auth`, #107). Direct instantiation with misconfigured options — no `TokenEndpoint`/`Domain`, a non-absolute or non-http `TokenEndpoint`, or a `Domain` ending in `/oauth/token` — throws `InvalidOperationException` from the constructor instead of at the first `GetTokenAsync` call. DI users registering through `AddCantonAuth` continue to see the same misconfiguration as an `OptionsValidationException` from the validator below.
- **`AddCantonAuth` validates options through a dedicated `IValidateOptions<ClientCredentialsOptions>` instead of `ValidateDataAnnotations`** (`Canton.Ledger.Auth`, #107). Misconfiguration now surfaces as a clean `OptionsValidationException` — previously the DataAnnotations property sweep invoked the throwing `TokenGenerationEndpoint` getter and crashed with `TargetInvocationException`. Validation failure messages now come from `ClientCredentialsOptions.Validate` (e.g. "ClientId must not be whitespace." instead of "The ClientId field is required.").
- **`LedgerClient.TryExerciseAsync<TResult>` and `TrySubmitAndWaitForTransactionAsync` now share a single internal submit path** (`Canton.Ledger.Grpc.Client`). Both route through one private `TrySubmitCoreAsync` that owns command building, header/deadline resolution, the gRPC call, response projection, and the `RpcException` → `DamlError`/`InfraError` mapping; only the `TransactionFormat` differs (`TryExerciseAsync` requests `LedgerEffects` + verbose, the plain submit path keeps the server-default `AcsDelta`). `TryExerciseAsync<TResult>` now unpacks its typed value via `TransactionResult.ExerciseResult<TResult>(choiceName)` instead of walking the raw protobuf. Consequences for `TryExerciseAsync` callers: the exercised event is now located by choice name only (no longer also keyed on the command's contract id), so a transaction containing more than one exercised event with that choice name — e.g. a choice whose body re-exercises the same choice on a child contract — now throws `InvalidOperationException` (the cardinality contract of `ExerciseResult<TResult>`) where the contract-id-keyed lookup previously disambiguated; the "no exercised event" not-found error message changed wording; and a choice that returns no `ExerciseResult` is normalized to `Unit` and yields `One` (previously threw). Caller-requested cancellation still propagates from `TryExerciseAsync` as before. `RpcException` failures are now logged on the shared path for both methods.
- **Bumped runtime transitive deps.** `Google.Protobuf` 3.35.0 → 3.35.1 (matches `daml-codegen-csharp` 0.1.8-preview.2) and all `Microsoft.Extensions.*` runtime packages (incl. `Http`) 10.0.8 → 10.0.9. No API or behaviour change; the package floors consumers inherit move up accordingly.

## [0.1.4] - 2026-06-04

### Added

- **`LedgerClient` and `AdminClient` now log a `Warning` at construction time when running in unauthenticated mode** (`ITokenProvider.None`). Each message names the concrete step to take — register an `ITokenProvider` or use the matching `AddLedgerClient`/`AddAdminClient` overload that accepts `authConfiguration` — so misconfigured apps surface the oversight immediately instead of failing with an opaque gRPC `UNAUTHENTICATED` error at the first API call.

- **Integration test project `Canton.Ledger.Grpc.Client.Integration.Tests`** — end-to-end round-trip of a rich Daml template (Int/Numeric/Text/Bool/Date/Party/Optional/List/nested Record + one choice) through a real Canton participant on `canton-localnet-internal`, proving the published `Daml.Runtime` + generated C# + gRPC `LedgerClient` create/subscribe/exercise path. Self-skips without a live localnet.

- **`ILedgerClient.TryExerciseAsync<TResult>`** — structured-outcome exercise overload required by the new `Daml.Ledger.Abstractions` 0.1.7 interface contract. `LedgerClient` implements this method; any other `ILedgerClient` implementation must add it.

### Fixed

- **`DamlValueConverter.ToProtoTemplateNameIdentifier` now throws `ArgumentException` on an empty package name** instead of silently emitting the package-id hash (#92). The hash form is rejected by Canton's ACS/update filter endpoints (`Invalid field packageId: ... expected a package name`), so the previous soft fallback re-introduced the exact failure it was meant to avoid — surfacing as a cryptic runtime gRPC error mid-stream; the method never falls back to the hash on the stream-filter path. `SubscribeAsync<T>` / `SubscribeActiveAsync<T>` compute the filter identifier eagerly, so the throw now fails fast at the subscribe call rather than on the first `await foreach`. The message names the offending template's module, entity, and package-id hash so an operator can trace it back to the DAR. Stream-filter path only; the command (create/exercise) path is unaffected and continues to use the hash via `ToProtoIdentifier`.

- **`SubscribeAsync<T>` and `SubscribeActiveAsync<T>` now reference templates by package name in their read-path filters.** Both stream filters previously sent the package hash in the `TemplateId.package_id` field; Canton's ACS/update filter endpoints reject that with `InvalidArgument: Invalid field packageId: ... expected a package name`, so every subscription failed against a real ledger. The filter now sends `#<T.PackageName>` (the smart-contract-upgrade package-name reference). The command path (create/exercise) is unchanged and continues to use the hash.

- `LedgerClient` and `AdminClient` no longer dispose the shared static `ActivitySource` when an instance is disposed. Previously, the first instance's `Dispose()` silently disabled tracing — `StartActivity` returned `null` on every subsequent instance, so OpenTelemetry (or any other `ActivityListener`) saw no further spans, with no warning or exception. Affects any process that disposes a `LedgerClient`/`AdminClient` and then constructs another.

### Removed — BREAKING for `ILedgerClient` implementors

- **`ExerciseAsync` overloads removed from `ILedgerClient`** (upstream `Daml.Ledger.Abstractions` 0.1.7). Any class that directly implements `ILedgerClient` must remove these methods from the interface implementation. *Callers* of `ILedgerClient.ExerciseAsync` are unaffected — the methods now live as extension methods on `LedgerClientExtensions` and resolve without source changes.

### Changed

- **Bumped `Daml.Ledger.Abstractions` and `Daml.Runtime` to `0.1.7`.** Picks up the `ILedgerClient` surface change described above (removed `ExerciseAsync`, added `TryExerciseAsync<TResult>`).

- **Bumped runtime transitive deps.** `Grpc.Net.Client` 2.76.0 → 2.80.0 (aligns with the `Grpc.Tools` 2.80.0 already pinned), `Google.Protobuf` 3.34.1 → 3.35.0 (matches `daml-codegen-csharp`), and all `Microsoft.Extensions.*` runtime packages (incl. `Http`) 10.0.7 → 10.0.8. No API or behaviour change; the package floors consumers inherit move up accordingly.
- **Test stack migrated to xUnit v3 + Microsoft.Testing.Platform coverage.** `xunit 2.9.3` + `xunit.runner.visualstudio 3.1.5` + `coverlet.collector 10.0.1` replaced by `xunit.v3 3.2.2` + `Microsoft.Testing.Extensions.CodeCoverage 18.0.6`. Test projects opt into the MTP runner via `tests/Directory.Build.props`, producing per-project `$(MSBuildProjectName).cobertura.xml` outputs — sidesteps the `XPlat Code Coverage` data-collector race that previously produced single-assembly coverage reports under solution-level parallelism. `coverlet.runsettings` (Coverlet/VSTest schema) replaced by `coverage.settings.xml` (Microsoft `<CodeCoverage>` schema); the scope changes from an explicit Include allowlist of four source assemblies to an exclude-only design (excludes `*.Tests.dll` and the generated-stub `Canton.Ledger.Grpc.dll`). The four source libraries are still the only ones that get instrumented today because they are the only non-test, non-generated assemblies in the build — a future `src/` addition will land in coverage by default unless explicitly excluded. CI workflow inlined (no longer calls the shared `csharp-ci.yaml@v1`) pending fleet-wide rollout — tracked in peacefulstudio/github-helper#95; the PR-comment renderer is `irongut/CodeCoverageSummary` (matching the `go-ci` reusable and the other C# repos) over the merged cobertura produced by `dotnet-coverage merge`.

## [0.1.2] - 2026-05-01

### Added

- **Typed subscription streams** in `Canton.Ledger.Grpc.Client`: `ILedgerClient.SubscribeAsync<T>(actAs, fromOffset, ct)` and `ILedgerClient.SubscribeActiveAsync<T>(actAs, ct)` wrap `UpdateService.GetUpdates` and `StateService.GetActiveContracts` with template-id filtering and project results to a typed `ContractStreamEvent<T>` discriminated record (`Created` with full payload + offset, `Archived`, `Exercised` with choice argument/result, `StreamError` for in-band gRPC failure). `IAsyncEnumerable<>` honours consumer backpressure; cancellation tears down the gRPC stream cleanly; mid-stream gRPC errors surface as a `StreamError` event rather than throwing — mirroring the outcome-typing discipline of `ExerciseOutcome<T>`. Caller-driven offset checkpointing only — the library does not persist `fromOffset`. (#55)
- **`ContractStreamEvent<T>.Checkpoint(long Offset)`** surfaces participant-emitted offset checkpoints from `UpdateService.GetUpdates`. Canton emits these on a participant-configured cadence regardless of the active filter; persisting `Checkpoint.Offset` lets a low-traffic subscription advance its resume offset during quiet periods, avoiding the re-process-from-stale-offset failure mode after a crash. (#55)
- **`ContractStreamEvent<T>.Assigned` / `Unassigned`** surface reassignment events on `SubscribeAsync<T>`, filtered by `T.TemplateId` the same way as `Created`/`Archived`. Each carries the on-ledger contract ID, the source/target synchronizer IDs, and the offset. `Assigned` additionally carries the re-emitted `CreateArguments` payload so consumers rebuilding state from a single stream stay correct on the target synchronizer. (#55)
- **`SubscribeActiveAsync<T>` includes in-flight reassignment entries** (`IncompleteAssigned`, `IncompleteUnassigned` from `StateService.GetActiveContracts`). These carry create-arguments for contracts that are mid-reassignment in multi-synchronizer deployments and are required for a complete ACS view. Previously they were silently dropped, yielding an under-reported snapshot. (#55)
- **`ILedgerClient.GetLedgerEndAsync(CancellationToken)`** returns the participant's current ledger-end offset. Compose with `SubscribeActiveAsync<T>` to snapshot-then-subscribe: capture the offset before draining the snapshot, then call `SubscribeAsync<T>` with that offset to stay current without missing or duplicating events. (#55)

  Cross-track follow-ups (TODO):
  - Broaden the `where T : ITemplate` constraint to `IDamlType` once `feat/interface-markers` lands on `dev`, so the streams can also dispatch on interface IDs computed by participant-side interface views.
  - Replace the `string actAs` parameter with the multi-party `SubmitterInfo` type once `feat/multi-party-submitters` (#56) ships.

- **Outcome-typed exercise API** in `Canton.Ledger.Grpc.Client`: `TrySubmitAndWaitForTransactionAsync`, `TryCreateAsync<X>`, and `TryExerciseForCreatedAsync<X>` return a single discriminated `ExerciseOutcome<T>` record instead of throwing. The outcome variants — `One`, `None`, `Many`, `DamlError`, `InfraError` — distinguish success (carrying a `T` payload), structured Canton/Daml errors (`DamlError` with a `DamlErrorCategory` enum, error ID, message, and `ErrorInfo.metadata`), and infrastructure failures (`InfraError`). Errors are decoded from the gRPC `grpc-status-details-bin` trailer's rich error model; missing/unparseable trailers fall back to `DamlErrorCategory.Unknown` without losing information. Lets consumers `switch` on outcomes instead of catching exceptions and parsing trailers manually. (#47)
- `ExerciseOutcome<T>` is unconstrained on `T`: success can carry a typed `ContractId<X>`, a raw `TransactionResult`, a composite Daml choice-result record, or any scalar — whatever shape the caller's API surface needs. Template-typed projection out of a transaction lives on `TransactionResultExtensions` (`Single<X>()`, `TrySingle<X>()`, `All<X>()` extension methods over `TransactionResult`, each constrained `where X : ITemplate`). (#47, #48)

### Changed

- **Lifted to upstream `Daml.Runtime` 0.1.4**: types `ExerciseOutcome<T>` (now in `Daml.Runtime.Outcomes` with variants renamed to `One` / `None` / `Many`), `DamlErrorCategory` (in `Daml.Runtime.Outcomes`), `TransactionResult` / `CreatedContract` / `TransactionResultExtensions` (in `Daml.Runtime.Contracts`), and `ContractStreamEvent<T>` (in `Daml.Runtime.Streams`, formerly canton's `ContractEvent<T>`). Local copies removed; canton consumes the upstream versions via `<PackageVersion Include="Daml.Runtime" Version="0.1.4" />`. The `ExerciseOutcome<T>.InfraError.StatusCode` field is now `int` (was `Grpc.Core.StatusCode`) so the type stays free of any transport-library dep; cast back to the typed enum when needed.
- **`ILedgerClient` interface lifted to `Daml.Ledger.Abstractions` 0.1.4**. Canton's `LedgerClient` now implements `Daml.Ledger.Abstractions.ILedgerClient` from upstream. Add `<PackageVersion Include="Daml.Ledger.Abstractions" Version="0.1.4" />`.
- **BREAKING:** `CreatedContract.TemplateId` is now `Daml.Runtime.Data.Identifier` (was `string`). Surfaces the parsed package/module/entity directly so `TransactionResult.Single<T>()` etc. can match by qualified name. (#47)

### Removed — BREAKING

- Deprecated throwing methods `ILedgerClient.CreateAsync<T>` and `ILedgerClient.SubmitAndWaitForTransactionAsync` (long `[Obsolete]`, see issue #47) are no longer part of the abstraction or canton's `LedgerClient`. Migrate to `TryCreateAsync` / `TrySubmitAndWaitForTransactionAsync` which return `ExerciseOutcome<T>` and let callers `switch` on the outcome instead of catching exceptions.
