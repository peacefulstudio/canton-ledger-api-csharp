## [0.4.0-preview.1] - 2026-07-18

_Skips the 0.3.x line — package versions ride the pinned `Daml.*` line (0.4.x ↔ Daml 0.4.x), while the preview number stays independent of `Daml.*`'s._

### Added

- **`IPqsClient.QueryAsync<TInterface, TView>` queries active contracts through a Daml interface, projecting each row's participant-computed interface view** (`Canton.Ledger.Pqs.Client`). Routes through the same PQS `active(name)` function as the template overload but passes the interface's package-name-qualified identifier (`{packageName}:{moduleName}:{interfaceName}`), and deserializes each row's JSONB `payload` — the interface *view* record, not the implementing template's fields — into the new `InterfaceContract<TInterface, TView>` result (`Id` typed to the interface, `View` the deserialized view). Both type arguments are explicit (e.g. `QueryAsync<IHolding, HoldingView>()`) because the queried interface and its view are distinct types, tied by the `IHasView<TView>` constraint; the existing template `QueryAsync<T>` overload is unchanged. A live-PQS LocalNet round-trip proves the interface row's `payload` is the view projection.
- **`AddPqsClient` opens PQS connections from a DI-registered `NpgsqlDataSource` when one is present** (`Canton.Ledger.Pqs.Client`). If the container has an `NpgsqlDataSource` registered (for example via `AddNpgsqlDataSource`), the PQS client now borrows its pooled connections from that data source; with no data source registered it continues to open connections directly from `PqsClientOptions.ConnectionString`, exactly as before. This makes the query-execution and row-mapping paths unit-testable through an internal connection seam without a live database. No public API change.
- **LocalNet REST conformance lane for the JSON Ledger API adaptation layer** (`Canton.Ledger.Rest.Client.Integration.Tests`). A new integration project drives the generated Refit surface registered by `AddRestLedgerApis` against a real participant and pins the current encoding gaps between the proto-generated POCOs and the JSON Ledger API: camelCase response keys (`userManagement`, `primaryParty`, `partyDetails`) deserialize to `null` and land in `AdditionalProperties` (delta D1), the numeric `offset` on `/v2/state/ledger-end` fails to bind the string-typed `GetLedgerEndResponse.Offset` (delta D2), and snake_case query parameters (`page_size`) are silently ignored by the server (delta D3) — alongside liveness/readiness and authenticated-user round-trips that already pass. A same-minor `LedgerApiVersionSkewGuard` (unit-tested) skips the lane when the participant drifts off the vendored Canton 3.4 spec, since conformance results are not trustworthy across Canton minors. Self-skips without a live LocalNet, matching the other integration lanes.

- **`ICantonLedgerClient.SubscribeLedgerEffectsAsync<T>` streams the ledger-effects transaction shape** (`Canton.Ledger.Grpc.Client`). Emits `ContractStreamEvent<T>.Created` and `.Exercised` over the half-open `(fromOffset, toOffset]` window with witness-based visibility; a consuming exercise (`Exercised.Consuming` is `true`) is a contract's archival on this shape, so there is no separate `.Archived` event. Complements the ACS-delta `SubscribeAsync<T>` and takes a `SubmitterInfo` (no `Party` convenience overload). Wires the `ILedgerStreamer` member that `Daml.* 0.4.0-preview.2` adds.

- **`IServiceCollection.AddValidatedOptions<T>` helper for binding options with eager startup validation** (`Canton.Ledger.Kernel`). Binds an options type from `IConfiguration` (or a configure delegate) and marks it for `ValidateOnStart()` in one call, returning the `OptionsBuilder<T>` so callers chain their own `ValidateDataAnnotations()` or a custom `IValidateOptions<T>`. The gRPC, PQS, REST, and Canton-auth client registrations now share this helper; their existing binding, validation, and lifetime semantics are unchanged.

### Changed — BREAKING

- **`SubscribeAsync<T>` now streams the `ACS_DELTA` transaction shape (`Created` / `Archived`), never `Exercised`** (`Canton.Ledger.Grpc.Client`). The live subscribe stream previously hardcoded `LEDGER_EFFECTS`, which delivers `CreatedEvent` and `ExercisedEvent` but never a standalone `ArchivedEvent` — so the projector's `ContractStreamEvent<T>.Archived` arm was unreachable, a consumer following the documented "cache on `Created` / `Archived`, checkpoint on the last observed offset" pattern never evicted archived contracts (they stayed cached forever and later exercised into `CONTRACT_NOT_FOUND`), and — because `LEDGER_EFFECTS` matches on **witnesses** while the `SubscribeActiveAsync` snapshot matches on **stakeholders** — a restart (snapshot + resume) reconstructed a different contract set than the live stream had delivered. `ACS_DELTA` matches on stakeholders, so archives now surface as `ContractStreamEvent<T>.Archived` and snapshot + resume reconstructs a consistent set. No `ArchivedEvent` is synthesized (synthesis cannot fix the witnesses-vs-stakeholders mismatch); the effects view is not dropped but moves to a dedicated upstream `SubscribeLedgerEffectsAsync<T>` on `ILedgerStreamer`. The exercise-result readback (`TryExerciseAsync`) and point reads (`GetUpdateByOffsetAsync` / `GetUpdateByIdAsync`) are unaffected — they keep `LEDGER_EFFECTS` to decode choice results. Migration: consume `Archived` for the cache/checkpoint pattern; any consumer switching over `ContractStreamEvent<T>.Exercised` on the default stream no longer receives those events and must move per-choice/effects observation to the upstream `SubscribeLedgerEffectsAsync<T>`.
- **`SubscribeActiveAsync<T>` and `CompletionStreamAsync` now surface a mid-stream transport fault in-band as a terminal `StreamError` instead of throwing** (`Canton.Ledger.Grpc.Client`). The three streaming reads previously disagreed on the fault contract: `SubscribeAsync<T>`/`SubscribeLedgerEffectsAsync<T>` yielded a terminal `ContractStreamEvent<T>.StreamError`, while `SubscribeActiveAsync<T>` rethrew the raw `RpcException` and `CompletionStreamAsync` threw — so an app that safely drained the live subscribe stream (matching `StreamError`, no `try`/`catch`) crashed on a mid-snapshot or mid-completion fault. All three now yield a terminal `StreamError` carrying `(int StatusCode, string Message)`: `SubscribeActiveAsync<T>` → `AcsSnapshotEntry<T>.StreamError` (in place of the success-path terminal `Checkpoint`, so a faulted snapshot hands over no resume offset), and `CompletionStreamAsync` → the new `CompletionStreamEvent.StreamError` variant. Caller cancellation is unchanged — it still throws `OperationCanceledException`. Migration: a consumer that wrapped `SubscribeActiveAsync`/`CompletionStreamAsync` in `try { … } catch (RpcException)` must instead match the terminal `StreamError` inside the `await foreach`; `SubscribeAsync` consumers are unaffected.
- **`ContractStreamEvent<T>.Unclassified.Kind` is now the strongly-typed `Daml.Runtime.Streams.UnclassifiedKind` enum instead of a free-form `string`** (`Canton.Ledger.Grpc.Client` / `Canton.Ledger.Rest.Client`). Adopting `Daml.* 0.4.0-preview.2`, the client drops its internal kebab-case kind catalogs and projects every unclassified event onto the upstream discriminator consumers `switch` on. An event the client cannot map to a known reason surfaces as `UnclassifiedKind.Unknown` carrying the raw transport descriptor (the former kind string, e.g. `"incomplete-unassigned"`, or the wire event-case name) on the new `Unclassified.RawKind` property, which is non-`null` exactly when `Kind` is `Unknown`. The ACS snapshot's `AcsSnapshotEntry<T>.Unclassified.Kind` stays a `string` (unchanged type), but its values now read as the enum member name — e.g. `"CreatedEvent"` in place of the former `"created-event"` — except for unknown entries, which keep their raw descriptor. Migration: `switch` on `event.Kind` against `UnclassifiedKind` members, and read `event.RawKind` for the `Unknown` case.

### Changed

- **Bump `Daml.Runtime` / `Daml.Ledger.Abstractions` to `0.4.0-preview.2`** (build). A consumer restoring the client transitively acquires the `0.4.0-preview.2` Daml line; the committed `richtypes` integration fixtures are regenerated against the matching `dpm-codegen-cs:0.4.0-preview.2` emitter (byte-identical output — no codegen shape drift).

### Fixed

- **Library `await`s now call `ConfigureAwait(false)`, preventing `SynchronizationContext` deadlocks for consumers that block on returned Tasks** (`Canton.Ledger.Grpc.Client` / `Canton.Ledger.Kernel` / `Canton.Ledger.Pqs.Client` / `Canton.Ledger.Rest.Client`). Every `await` in the shipped libraries now resumes on the thread-pool context instead of reposting to a captured `SynchronizationContext`, so a caller that blocks on a returned `Task` (`.Result` / `.Wait()`) under a single-threaded context (WPF, WinForms, classic ASP.NET) no longer risks deadlock, and continuations skip the needless context hop. `CA2007` is enforced as a build error across `src/` so the guarantee holds going forward. No public API or async behavior change.
- **Numeric proto conversion now covers the full Daml `Numeric` range and precision, fixing an overflow throw and silent precision loss** (`Daml.Runtime.Grpc`). `DamlValueConverter` previously round-tripped numerics through `decimal`: on the read path a wire value beyond `decimal`'s range (for example `1e30`) was rejected with a `FormatException`, and a value with more than ~28 significant digits was silently rounded (a `Numeric 30` like `0.12345678901234567890123456789012345` came back as `…5679`). Both paths now delegate to the upstream `DamlNumeric.ToCanonicalString()` / `DamlNumeric.TryParseCanonical(...)` (`Daml.* 0.4.0-preview.2`), so proto `Value` ↔ `DamlValue` preserves up to 38 significant digits losslessly and never overflows within the Daml `Numeric` range. The canonical wire encoding is unchanged (trailing zeros stripped, one forced fractional digit, no scientific notation); a non-canonical Numeric still throws `FormatException`.
- **Token acquisition now has a bounded, configurable timeout instead of inheriting `HttpClient`'s 100-second default** (`Canton.Ledger.Kernel`). The `CantonAuth` client's token fetch runs under a single refresh lock, so a hung identity provider could stall every authenticated call for up to 100 seconds each, queued serially. A new `ClientCredentialsOptions.TokenAcquisitionTimeout` (`TimeSpan`, default 30 seconds, validated positive) now bounds each fetch — applied both to the DI-registered `CantonAuth` `HttpClient.Timeout` and enforced inside `ClientCredentialsProvider`. A fetch that exceeds the budget surfaces as a `TimeoutException` whose message attributes the failure to token acquisition and names the endpoint (no secrets), rather than a generic `TaskCanceledException`. Caller-initiated cancellation still surfaces as `OperationCanceledException`. Note that `LedgerClientOptions.Timeout` governs only the gRPC call, not token acquisition.
- **`RetryOptions` now validates at startup, rejecting a negative `MaxRetryAttempts` or `Delay`** (`Canton.Ledger.Kernel` / `Canton.Ledger.Grpc.Client`). A negative `MaxRetryAttempts` previously let Polly retry effectively forever, and a negative `Delay` surfaced only as an opaque failure deep inside the Polly pipeline build on the first RPC. `RetryOptions` now carries `[Range(0, int.MaxValue)]` on `MaxRetryAttempts` and validates `Delay >= TimeSpan.Zero` via `IValidatableObject`, and `LedgerClientOptions` recurses into its nested `Retry` so the existing `ValidateDataAnnotations().ValidateOnStart()` pipeline fails fast at host startup with a clear message — runtime data-annotation validation does not descend into nested options on its own.
- **`AdminClient` calls now run through the same call pipeline as `LedgerClient`, gaining the retry policy and cancellation reclassification they previously bypassed** (`Canton.Ledger.Grpc.Client`). Every party/user/package admin operation hand-rolled its own per-call envelope (auth headers, deadline, tracing) and invoked the raw gRPC stub directly, so — unlike `LedgerClient`/`SubmissionClient` behind the same package — admin calls ignored `LedgerClientOptions.Retry` entirely and surfaced a caller-cancelled call as a raw `RpcException(StatusCode.Cancelled)`. Admin unary calls (including each page of the paginated `ListKnownParties`/`ListUsers`/`ListVettedPackages` reads) now honor the configured transient-retry pipeline, and a caller cancellation surfaces as `OperationCanceledException` for parity with the rest of the client. Public API surface is unchanged.
- **Source-visible cancellation change on `LedgerClient` unary reads:** collapsing the duplicated call envelope onto the shared helper also routes `GetLedgerEndAsync`, `GetLedgerApiVersionAsync`, `GetConnectedSynchronizersAsync`, `GetUpdateByOffsetAsync`, and `GetUpdateByIdAsync` through the same cancellation reclassification. These five methods previously surfaced a caller-cancelled call as `RpcException(StatusCode.Cancelled)`; they now throw `OperationCanceledException` (with the transport `RpcException` as `InnerException`), matching the streaming surface. A caller that explicitly caught `RpcException(Cancelled)` on these methods must catch `OperationCanceledException` instead.
- **`AdminClient` now validates its reference and id arguments at each public entry point, throwing a caller-attributable `ArgumentNullException`/`ArgumentException` instead of a bare `NullReferenceException` or a confusing server-side error** (`Canton.Ledger.Grpc.Client`). `AllocatePartyAsync` (`partyIdHint`), `CreateUserAsync` (`userId`), `GetUserAsync` (`userId`), `GrantUserRightsAsync`/`RevokeUserRightsAsync` (`userId`) reject null, empty, or whitespace ids; `GetPartiesAsync` (`partyIds`), `GrantUserRightsAsync`/`RevokeUserRightsAsync` (`rights`), and `CreateUserAsync` (`primaryParty`) reject null — bringing the remaining methods in line with `GetPackageAsync`/`UploadDarAsync`, which already validated. `CreateUserAsync` still accepts an empty `primaryParty` (a user without a primary party) and `ListUserRightsAsync` still accepts an empty `userId` (the authenticated user), both of which remain valid inputs. Valid calls are unaffected.

### Security

- **The REST (JSON Ledger API) client now warns when it would send a bearer token over a plaintext `http` connection, mirroring the gRPC client's insecure-transport check** (`Canton.Ledger.Rest.Client`). A `RestLedgerClientOptions.HttpAddress` pointing at an `http://` endpoint attaches `Authorization: Bearer …` to every request on a cleartext channel, where anyone on the network path can read and replay the token — previously with no signal. `BearerTokenHandler` now logs a single Warning (naming the endpoint) the first time it sends a token over `http`; `https` and unauthenticated (`ITokenProvider.None`) traffic stay silent. The empty-token and unauthenticated-skip guards shared with the gRPC path now live in one place, `TokenProviderExtensions.ResolveBearerTokenAsync` in `Canton.Ledger.Kernel`.

### Added

- **`LedgerClient` unary operations now accept an optional per-call `timeout` that maps to the gRPC call deadline** (`Canton.Ledger.Grpc.Client`). `TryExerciseAsync`, `SubmitAndWaitAsync`, `TrySubmitAndWaitForTransactionAsync`, `TryCreateAsync`, `TryExerciseForCreatedAsync`, and `GetLedgerEndAsync` each take a `TimeSpan? timeout = null` immediately before the trailing `CancellationToken`. When set, it is applied as `CallOptions.Deadline` (`DateTime.UtcNow + timeout`) on each attempt and takes precedence over the client-wide `LedgerClientOptions.Timeout` default; a deadline overrun stops the participant working on the call and surfaces as an `ExerciseOutcome.InfraError` (or, for `GetLedgerEndAsync`, the transport `RpcException`). `null` leaves the existing `LedgerClientOptions.Timeout` behaviour unchanged. Wires the `ILedgerClient` deadline surface added upstream in `Daml.Ledger.Abstractions`. Streaming operations deliberately take no wall-clock deadline — the `CancellationToken` remains their sole time bound.
- **`SubscribeAsync<T>` accepts an optional end-inclusive `toOffset` for bounded historical replay** (`Canton.Ledger.Grpc.Client`). Passing `toOffset` sets the Ledger API's `GetUpdatesRequest.end_inclusive`, so the stream yields updates in `(fromOffset, toOffset]` and then completes normally — no error, no cancellation — for audits, backfills, and deterministic tests over a fixed ledger range. `null` (the default) leaves the subscription open-ended, exactly as before. Wires the `toOffset` parameter added upstream on `ILedgerClient.SubscribeAsync`.
- **`SubscribeActiveAsync<T>` accepts an optional `activeAtOffset` and now ends every snapshot with a terminal `ContractStreamEvent<T>.Checkpoint` carrying the snapshot's effective offset** (`Canton.Ledger.Grpc.Client`). When `activeAtOffset` is supplied it is used directly as the ACS `active_at_offset` (the client no longer queries ledger end); when `null` the client resolves the current ledger end as before. In both cases the stream emits a final `Checkpoint(effectiveOffset)` after the active contracts — even for an empty snapshot — so a consumer resumes `SubscribeAsync` from exactly that offset for a gapless, duplicate-free snapshot-then-subscribe handover. Wires the `activeAtOffset` parameter and terminal-checkpoint contract added upstream on `ILedgerClient.SubscribeActiveAsync`. Source-visible for any consumer whose `switch` over the snapshot's `ContractStreamEvent<T>` did not expect a `Checkpoint`: handle it as the terminal event (persist `Offset`, do not treat it as a contract).

### Changed — BREAKING

- **`TransactionResult.ExerciseResult<TReturn>` / `AllExerciseResults<TReturn>` now return `TReturn?` / `IReadOnlyList<TReturn?>`, and `TryExerciseAsync<TResult>` yields `ExerciseOutcome<TResult>.None` when a choice result legitimately decodes to `null`** (`Canton.Ledger.Grpc.Client`). A unit- or `Optional`-shaped choice return decodes to `null`; the extensions previously laundered that `null` through a non-null `TReturn` with the `!` operator, so a consumer received a `null` typed as non-null and hit a `NullReferenceException` at their own call site with nothing pointing back to the decode. The return types are now honestly nullable, and the submission path maps a null decode to the existing `None` outcome instead of constructing `One(null)`. Migration: treat the extension results as nullable (assert non-null at the call site for choices you know return a value), and handle `ExerciseOutcome<TResult>.None` from `TryExerciseAsync<TResult>` where a reference-typed choice result can be unit/`Optional`-shaped.
- **Bumping to `Daml.Runtime` / `Daml.Ledger.Abstractions` `0.4.0-preview.1` retypes ledger offsets as `Daml.Runtime.LedgerOffset` and makes `SubscribeActiveAsync<T>` yield the dedicated `AcsSnapshotEntry<T>` snapshot type** (`Canton.Ledger.Grpc.Client`). The published release replaced the raw `long` offset with the typed `LedgerOffset` struct across the read/stream surface: `GetLedgerEndAsync` returns `LedgerOffset`; `SubscribeAsync<T>`'s `fromOffset`/`toOffset` and `SubscribeActiveAsync<T>`'s `activeAtOffset` are `LedgerOffset?`; and every `ContractStreamEvent<T>` / `AcsSnapshotEntry<T>` variant's `Offset` is a `LedgerOffset`. Build one with `LedgerOffset.At(long)` and read the underlying value with `.Value`. `SubscribeActiveAsync<T>` now returns `IAsyncEnumerable<AcsSnapshotEntry<T>>` (variants `Created` / `Unclassified` / `Checkpoint`) instead of `ContractStreamEvent<T>` — an ACS snapshot models only active contracts, its terminal checkpoint, and entries it could not classify, so it has no `Assigned`/`Unassigned` variant. An in-transit `IncompleteUnassigned` entry accordingly surfaces as `AcsSnapshotEntry<T>.Created` followed by `AcsSnapshotEntry<T>.Unclassified(offset, "unassigned-event")` (superseding the earlier `Created`-then-`Unassigned` shape, which the new snapshot type can no longer express). Migration: read offsets via `offset.Value`, construct them with `LedgerOffset.At(...)`, and switch `SubscribeActiveAsync` consumers over `AcsSnapshotEntry<T>`.
- **`IAdminClient.AllocatePartyAsync` no longer takes a `displayName` parameter** (`Canton.Ledger.Grpc.Client`). The parameter was silently discarded: Ledger API v2's `AllocatePartyRequest` has no `display_name` field (the proto reserves field 2, "Formerly display_name"), so `AllocatePartyAsync("alice", displayName: "Alice Trading Desk")` sent no display name while the XML docs promised "Optional display name for the party". No behavior is lost because none existed — drop the argument. Migration from 0.1.x: callers who passed `displayName` as a **named** argument (`displayName:`) get a compile error. Callers who passed it **positionally** (`AllocatePartyAsync("alice", "Alice Trading Desk")`) get **no** compile error — the second argument silently rebinds to `synchronizerId` (both are `string?`, occupying the same position 2), and the bogus synchronizer id is then rejected by the participant at call time. Audit positional call sites, not just named ones.
- **`UserDetails` no longer carries a `Rights` list — read a user's rights back with the new `IAdminClient.ListUserRightsAsync`** (`Canton.Ledger.Grpc.Client`). `CreateUserAsync`, `GetUserAsync`, and `ListUsersAsync` returned `UserDetails.Rights = Array.Empty<UserRight>()` unconditionally — the Ledger API `User` proto carries no rights, so the property advertised a value it never filled, and a consumer that granted `ActAs(party)` and read the user back saw zero rights and concluded the grant failed. The property is removed rather than populated because filling it would hide a per-user follow-up `ListUserRights` RPC inside every list/read call. Migration: replace `userDetails.Rights` with `await adminClient.ListUserRightsAsync(userDetails.UserId)`.
- **An OAuth token endpoint with a plaintext `http` scheme is now rejected by default — opt in with `ClientCredentialsOptions.AllowInsecureTokenEndpoint`; authenticated gRPC clients warn when configured to send bearer tokens over `http`** (`Canton.Ledger.Kernel`, `Canton.Ledger.Grpc.Client`). `ClientCredentialsProvider` POSTs `client_id` + `client_secret` as a cleartext form body when the resolved token endpoint uses `http`, so an on-path attacker could harvest a long-lived secret; `ClientCredentialsOptions.Validate` and `TokenGenerationEndpoint` now fail such configs — whether from an explicit `TokenEndpoint` or an absolute-`http` `Domain` — with an actionable message unless the new `AllowInsecureTokenEndpoint` flag is set (e.g. for localhost development), and the provider logs a Warning at construction whenever a plaintext endpoint is actually used. `LedgerClient`/`AdminClient` constructed with a real `ITokenProvider` against an `http://` `GrpcAddress` attach `authorization: Bearer …` to every call on a cleartext channel; they now log a construction-time Warning naming the endpoint (unauthenticated `http` is unchanged and keeps its existing unauthenticated-mode warning). Breaking only for configs that already pointed `TokenEndpoint`/`Domain` at an `http` URL — set `AllowInsecureTokenEndpoint = true` to restore them deliberately.
- **`IAdminClient.ListKnownPartiesAsync` and `ListUsersAsync` now transparently follow server pagination and return the complete result set; the `pageToken` parameter is removed** (`Canton.Ledger.Grpc.Client`). Both methods previously returned only the first page and discarded the response's `next_page_token`, so a participant with more parties/users than `pageSize` silently yielded a truncated list — and the `pageToken` parameter offered no way to continue, because tokens are opaque and server-generated so a caller could never supply the next one. Both methods now loop on `page_token = next_page_token` until the server returns an empty token, exactly as `ListVettedPackagesAsync` already did, and throw `InvalidOperationException` when the server echoes back the token that was just sent (non-progressing pagination). `pageSize` remains as the per-round-trip fetch size. Source-breaking only for callers that passed the dead `pageToken` argument — delete it; the methods now return everything.
- **The fire-and-forget submission method `Submit` is renamed to `SubmitAsync` on `ICantonLedgerClient` and `LedgerClient`** (`Canton.Ledger.Grpc.Client`). The method returns a `Task` but lacked the `Async` suffix that the .NET naming convention — and the rest of this client surface — require. The `Submit`/`SubmitAsync` name is reserved for exactly this fire path (distinct from `SubmitAndWaitAsync`). Migration: rename call sites from `client.Submit(...)` to `client.SubmitAsync(...)`; the signature and behavior are unchanged.
- **`PackageArchive` and `ConnectedSynchronizer` now expose typed values instead of raw wire primitives, and `GetPackageAsync` no longer throws on an unrecognized hash function** (`Canton.Ledger.Grpc.Client`). `PackageArchive.Payload` changes from `byte[]` to `ReadOnlyMemory<byte>` and the record now compares payloads structurally, so two archives with equal bytes are equal — a `byte[]` compared by reference, so two identical downloads never matched. `PackageArchive.HashFunction` changes from `string` to a new `HashFunction` enum (`Sha256`, `Unrecognized`) and `ConnectedSynchronizer.Permission` changes from `string` to a new `SynchronizerPermissionLevel` enum (`Unspecified`, `Submission`, `Confirmation`, `Observation`, `Unrecognized`); switch over the enum members instead of string-matching `"Sha256"`/`"Submission"` or the raw integer that an undefined proto value used to stringify to. A hash function or permission value this SDK version does not recognise now maps to the enum's `Unrecognized` member — in particular `GetPackageAsync` no longer throws `InvalidOperationException` for an unrecognized hash function but returns a `PackageArchive` whose `HashFunction` is `HashFunction.Unrecognized`. Migration: read `archive.Payload.Span` / `archive.Payload.ToArray()` for the bytes, and compare `archive.HashFunction` / `synchronizer.Permission` against the new enum members.
- **`LedgerClient.CompletionStreamAsync` now returns `IAsyncEnumerable<CompletionStreamEvent>` (was `IAsyncEnumerable<Completion>`) and surfaces the participant's `OffsetCheckpoint`s instead of silently dropping them** (`Canton.Ledger.Grpc.Client`). Canton emits checkpoints on the completion stream precisely so a consumer can detect command timeout and obtain "an offset which can be used to restart consumption"; the client discarded every non-`Completion` response, making the "consumer owns its own offset" contract unimplementable during quiet periods — a resume offset frozen at the last completion falls arbitrarily far behind, forcing re-processing or `PARTICIPANT_PRUNED_DATA_ACCESSED` failures on reconnect. Each response now maps to a small union mirroring the update stream's `ContractStreamEvent<T>`: `CompletionStreamEvent.CommandCompleted(Completion)` wraps the raw completion, and `CompletionStreamEvent.Checkpoint(Offset)` carries the checkpoint offset — persist it to keep the resume offset advancing even when no completions arrive. Migration: pattern-match the yielded events (`is CompletionStreamEvent.CommandCompleted { Completion: var completion }`) where code previously consumed `Completion` directly.

### Added

- **A typed reassignment write surface — `UnassignCommand`/`AssignCommand` submitted through `ICantonLedgerClient.SubmitReassignmentAsync` (fire) or `TrySubmitAndWaitForReassignmentAsync<T>` (await)** (`Canton.Ledger.Grpc.Client`). Multi-synchronizer reassignment could previously only be driven by dropping to the raw generated `CommandSubmissionService.SubmitReassignment` stub. The client now exposes the two honest submission modes, mirroring the async-submission slice: `SubmitReassignmentAsync(ReassignmentSubmission)` fires the reassignment through `CommandSubmissionService.SubmitReassignment` and returns the effective `CommandId` (minted when omitted) for correlating the completion, while `TrySubmitAndWaitForReassignmentAsync<T>(ReassignmentSubmission)` awaits `CommandService.SubmitAndWaitForReassignment` and projects the result into the typed read-side `ContractStreamEvent<T>.Unassigned`/`.Assigned` variant wrapped in `ExerciseOutcome<T>` — one typed representation whether a reassignment is observed (via `SubscribeAsync`) or caused. `UnassignCommand(contractId, source, target)` and `AssignCommand(reassignmentId, source, target)` both take **required** source and target synchronizer ids (a reassignment names both endpoints, distinct from a normal command's optional per-submission synchronizer pin); construct a submission with `ReassignmentSubmission.Of(command, submitter)` and refine it with `WithCommandId`/`WithWorkflowId`/`WithSubmissionId`. The client does not orchestrate the unassign→assign dance — the consumer captures the `reassignment_id` from the unassigned event and passes it to a follow-up `AssignCommand`. Note: the projected `Unassigned` variant does not yet carry `reassignment_id`/`reassignment_counter` (sealed upstream `Daml.Runtime` records awaiting a release); read those off the raw completion/update stream in the meantime.
- **The gRPC channel now sends HTTP/2 keep-alive pings by default and `LedgerClientOptions` exposes hooks to tune or replace the channel** (`Canton.Ledger.Grpc.Client`). `LedgerClient` and `AdminClient` hardcoded `GrpcChannelOptions` to message sizes only, and .NET gRPC disables client keep-alive by default — so behind a NAT or L4 load balancer with an idle timeout, a silently dropped connection (LB failover, NAT rebind) left a pure `SubscribeAsync`/`CompletionStreamAsync` reader with `deadline: null` hung forever, and the channel-injecting constructors were internal so operators could not enable keep-alive at all. Both clients now build their channel through a shared factory that configures a `SocketsHttpHandler` with `KeepAlivePingDelay` (default 60s) and `KeepAlivePingTimeout` (default 20s), surfaced as `LedgerClientOptions.KeepAlivePingDelay`/`KeepAlivePingTimeout` for tuning via configuration. A new `LedgerClientOptions.ConfigureChannel` (`Action<GrpcChannelOptions>?`) hook runs after the SDK applies its defaults, letting operators override any channel option — including swapping in a caller-owned `HttpMessageHandler` — without reaching for an internal constructor. - **Reassignment (multi-synchronizer) events now flow end-to-end through `SubscribeAsync`/`SubscribeActiveAsync` and arrive correctly typed** (`Canton.Ledger.Grpc.Client`). Three defects made a contract's cross-synchronizer moves invisible or mis-typed. (1) The live subscription request set only `update_format.include_transactions` and never `include_reassignments`, and Canton emits `Assigned`/`Unassigned` updates only when that flag is set ("If unset, no (un)assignments are emitted in the stream") — so `ContractStreamEvent<T>.Assigned`/`Unassigned` never fired, the reassignment projection arm was dead code, and a contract's synchronizer assignment went permanently stale (later submissions pinned to the old `SynchronizerId` failed). `SubscribeRequestBuilder` now sets `UpdateFormat.IncludeReassignments` mirroring the transaction event format (the same party filters and template/interface filter), so reassignment updates are delivered. (2) `MarkerMatcher<T>.MatchesProtoUnassigned` returned `false` for every interface marker, so an interface-typed subscription surfaced all `UnassignedEvent`s as `Unclassified`; an `UnassignedEvent` arriving under the interface reassignment filter is ours by construction, so it now classifies as a typed `ContractStreamEvent<T>.Unassigned`. (3) `SubscribeActiveAsync` mapped an `incomplete_unassigned` ACS entry to a single active `Created` on the unassignment's **source** synchronizer, so the cache claimed the contract was active there even though the reassignment protocol makes it inactive pending assignment (exercises rejected until the `Assigned` event self-heals the view); the entry now surfaces as `Created` (on source) **followed by** `Unassigned` (source→target), so a consumer rebuilding state sees the in-transit departure instead of a false active contract. On Unix a bare filesystem path such as `/var/run/participant.sock` parsed as a `file://` URI with an empty host, and other non-http(s) inputs (`file://…`, `ftp://…`, `unix://…`, or a scheme-less `host:port` whose "scheme" swallowed the host) silently yielded a `("", 80)`-shaped endpoint — so the client emitted spans tagged with an empty `server.address` right up until `GrpcChannel.ForAddress`, a few lines later in the same constructor, rejected the identical address with a less specific `InvalidOperationException("No address resolver configured for the scheme …")`. An event whose value cannot be decoded — a `Numeric` beyond .NET `decimal`'s ~7.9e28 ceiling (honest ledger data: Ledger API `Numeric n` carries up to 38 digits), a proto `Value` with no sum case set, or a malformed record — previously threw out of the `SubscribeAsync`/`SubscribeActiveAsync` iterators and killed the consumer's `await foreach`; reconnecting from the last checkpoint re-read the same event, a permanent poison loop. With `LedgerClientOptions.Retry` enabled, a first attempt can commit while its response is lost (`Unavailable`/`DeadlineExceeded`); the retry resubmits the same `command_id` and the participant answers `ALREADY_EXISTS`/`DUPLICATE_COMMAND` — proof the intended ledger change already landed, which Canton's command-deduplication docs mandate reporting as success. ### Changed — BREAKING

- **The typed subscription stream never silently drops an event — unclassifiable events surface as `ContractStreamEvent<T>.Unclassified`** (`Canton.Ledger.Grpc.Client`). `ContractStreamProjector` previously hit a silent `continue` whenever it could not classify a delivered event to the subscribed marker `T`, dropping it from the stream. Source-breaking for any consumer whose `switch` over `ContractStreamEvent<T>` is exhaustive: add an `Unclassified` arm — persist `Offset` to advance the resume point, log `Kind`, and do not treat it as your typed contract. Member of the v0.2.0 breaking bundle. The active-contract snapshot path (`SubscribeActiveAsync`) reaches the same parity below.
- **`SubscribeActiveAsync<T>` now returns `IAsyncEnumerable<ContractStreamEvent<T>>` (was `IAsyncEnumerable<ContractStreamEvent<T>.Created>`), so the active-contract snapshot reaches no-silent-drop parity with the live stream** (`Canton.Ledger.Grpc.Client`). An `ActiveContract`/`IncompleteUnassigned`/`IncompleteAssigned` snapshot entry whose created event cannot be paired with a synchronizer id now yields `ContractStreamEvent<T>.Unclassified(Offset, UnclassifiedKind.MissingSynchronizerId)` instead of being logged and dropped; an entry whose template/interface does not match the subscribed marker `T` yields `Unclassified(Offset, UnclassifiedKind.CreatedEvent)` — the same kind the live stream already uses for that shape. Member of the v0.2.0 breaking bundle.

Typed subscription events lifted from a `Transaction` carry that transaction's `synchronizer_id`, and the active-contract path carries the synchronizer each contract is active on, so a consumer reconstructing state across a multi-synchronizer topology can attribute every event to its synchronizer without a side lookup. Follows the upstream `Daml.Runtime` surface where `SynchronizerId` became a required constructor argument on these variants — source-breaking only for code that constructs them by hand; readers gain a property.

## [0.1.2] - 2026-05-01

### Added

- **Typed subscription streams** in `Canton.Ledger.Grpc.Client`: `ILedgerClient.SubscribeAsync<T>(actAs, fromOffset, ct)` and `ILedgerClient.SubscribeActiveAsync<T>(actAs, ct)` wrap `UpdateService.GetUpdates` and `StateService.GetActiveContracts` with template-id filtering and project results to a typed `ContractStreamEvent<T>` discriminated record (`Created` with full payload + offset, `Archived`, `Exercised` with choice argument/result, `StreamError` for in-band gRPC failure). `IAsyncEnumerable<>` honours consumer backpressure; cancellation tears down the gRPC stream cleanly; mid-stream gRPC errors surface as a `StreamError` event rather than throwing — mirroring the outcome-typing discipline of `ExerciseOutcome<T>`. Caller-driven offset checkpointing only — the library does not persist `fromOffset`.
- **`ContractStreamEvent<T>.Checkpoint(long Offset)`** surfaces participant-emitted offset checkpoints from `UpdateService.GetUpdates`. Canton emits these on a participant-configured cadence regardless of the active filter; persisting `Checkpoint.Offset` lets a low-traffic subscription advance its resume offset during quiet periods, avoiding the re-process-from-stale-offset failure mode after a crash.
- **`ContractStreamEvent<T>.Assigned` / `Unassigned`** surface reassignment events on `SubscribeAsync<T>`, filtered by `T.TemplateId` the same way as `Created`/`Archived`. Each carries the on-ledger contract ID, the source/target synchronizer IDs, and the offset. `Assigned` additionally carries the re-emitted `CreateArguments` payload so consumers rebuilding state from a single stream stay correct on the target synchronizer.
- **`SubscribeActiveAsync<T>` includes in-flight reassignment entries** (`IncompleteAssigned`, `IncompleteUnassigned` from `StateService.GetActiveContracts`). These carry create-arguments for contracts that are mid-reassignment in multi-synchronizer deployments and are required for a complete ACS view. Previously they were silently dropped, yielding an under-reported snapshot.
- **`ILedgerClient.GetLedgerEndAsync(CancellationToken)`** returns the participant's current ledger-end offset. Compose with `SubscribeActiveAsync<T>` to snapshot-then-subscribe: capture the offset before draining the snapshot, then call `SubscribeAsync<T>` with that offset to stay current without missing or duplicating events.

  Cross-track follow-ups (TODO):
  - Broaden the `where T : ITemplate` constraint to `IDamlType` once `feat/interface-markers` lands on `dev`, so the streams can also dispatch on interface IDs computed by participant-side interface views.
  - Replace the `string actAs` parameter with the multi-party `SubmitterInfo` type once `feat/multi-party-submitters` ships.

- **Outcome-typed exercise API** in `Canton.Ledger.Grpc.Client`: `TrySubmitAndWaitForTransactionAsync`, `TryCreateAsync<X>`, and `TryExerciseForCreatedAsync<X>` return a single discriminated `ExerciseOutcome<T>` record instead of throwing. The outcome variants — `One`, `None`, `Many`, `DamlError`, `InfraError` — distinguish success (carrying a `T` payload), structured Canton/Daml errors (`DamlError` with a `DamlErrorCategory` enum, error ID, message, and `ErrorInfo.metadata`), and infrastructure failures (`InfraError`). Errors are decoded from the gRPC `grpc-status-details-bin` trailer's rich error model; missing/unparseable trailers fall back to `DamlErrorCategory.Unknown` without losing information. Lets consumers `switch` on outcomes instead of catching exceptions and parsing trailers manually.
- `ExerciseOutcome<T>` is unconstrained on `T`: success can carry a typed `ContractId<X>`, a raw `TransactionResult`, a composite Daml choice-result record, or any scalar — whatever shape the caller's API surface needs. Template-typed projection out of a transaction lives on `TransactionResultExtensions` (`Single<X>()`, `TrySingle<X>()`, `All<X>()` extension methods over `TransactionResult`, each constrained `where X : ITemplate`).

### Changed

- **Lifted to upstream `Daml.Runtime` 0.1.4**: types `ExerciseOutcome<T>` (now in `Daml.Runtime.Outcomes` with variants renamed to `One` / `None` / `Many`), `DamlErrorCategory` (in `Daml.Runtime.Outcomes`), `TransactionResult` / `CreatedContract` / `TransactionResultExtensions` (in `Daml.Runtime.Contracts`), and `ContractStreamEvent<T>` (in `Daml.Runtime.Streams`, formerly canton's `ContractEvent<T>`). Local copies removed; canton consumes the upstream versions via `<PackageVersion Include="Daml.Runtime" Version="0.1.4" />`. The `ExerciseOutcome<T>.InfraError.StatusCode` field is now `int` (was `Grpc.Core.StatusCode`) so the type stays free of any transport-library dep; cast back to the typed enum when needed.
- **`ILedgerClient` interface lifted to `Daml.Ledger.Abstractions` 0.1.4**. Canton's `LedgerClient` now implements `Daml.Ledger.Abstractions.ILedgerClient` from upstream. Add `<PackageVersion Include="Daml.Ledger.Abstractions" Version="0.1.4" />`.
- **BREAKING:** `CreatedContract.TemplateId` is now `Daml.Runtime.Data.Identifier` (was `string`). Surfaces the parsed package/module/entity directly so `TransactionResult.Single<T>()` etc. can match by qualified name.

### Removed — BREAKING

- Deprecated throwing methods `ILedgerClient.CreateAsync<T>` and `ILedgerClient.SubmitAndWaitForTransactionAsync` (long `[Obsolete]`) are no longer part of the abstraction or canton's `LedgerClient`. Migrate to `TryCreateAsync` / `TrySubmitAndWaitForTransactionAsync` which return `ExerciseOutcome<T>` and let callers `switch` on the outcome instead of catching exceptions.

## [0.1.1] - 2026-04-24

### Added

- `ServiceCollectionExtensions.AddCantonLedger(IConfiguration)` convention-based registration in `Canton.Ledger.Grpc.Client`. Reads `Canton:Ledger` for client options and `Canton:Auth` for client-credentials auth; auth is registered whenever the `Canton:Auth` section has any populated value, so half-configured auth fails loudly at startup instead of silently falling back to unauthenticated. Consumers can replace bespoke `AddLedgerClient`/`AddAdminClient`/`AddCantonAuth` wiring with a single call that matches the canonical config layout used by Helm charts.

For bare hostnames, the token endpoint is `https://{Domain}/oauth/token`; for absolute URLs, the provided scheme and any path are preserved and `/oauth/token` is appended (`https://auth.example.com/tenant-a` → `https://auth.example.com/tenant-a/oauth/token`).
